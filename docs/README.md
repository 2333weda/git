# 项目文档（docs）

文档与代码同仓版本控制，修改走分支与 PR。所有文档均以需求说明书 V0.8 为准。

## 目录

| 目录 | 内容 | 状态 |
| --- | --- | --- |
| `requirements/` | 需求说明书（DOCX + PDF），版本号随修订递增 | ✅ V0.8 |
| `prototypes/` | 低保真原型：14 页截图集 PDF、4 张预览图、可交互 HTML 稿 | ✅ 已完成 |
| `design/` | 概要设计、详细设计、数据库设计、时序图 | ⬜ 待开始 |
| `api/` | 接口文档：路径、参数、返回、错误码（需与需求说明书表 3-2 一致） | ⬜ 待开始 |

## 原型 HTML 稿

`prototypes/html/` 下是可直接用浏览器打开的静态原型，文件名与需求说明书第 7 章页面编号一一对应：

- `html/miniprogram/` —— `s01-availability` ～ `s06-credit`，学生端 6 页
- `html/admin/` —— `m01-venues` ～ `m06-logs`，管理端 6 模块

打开方式：双击任一 HTML 文件即可；需要整套串联时在目录内起一个静态服务器（`python -m http.server`）。

## 归档要求

1. 文件名格式：`<文档名>-V<主>.<次>-<日期>.<扩展名>`，例如 `需求说明书-V0.9-20261201.docx`
2. 文档定稿后不要直接覆盖原文件，另存新版本号，旧版本保留以便追溯
3. 需求说明书改动必须同步表 3-1（约束）、表 3-3（约束与用例）、表 4-1（功能与用例）三张表，编号不得跳号
4. 图片资源放同级 `assets/`，用相对路径引用，避免外链失效
