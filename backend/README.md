# 后端工程（backend）

提供小程序与管理端共用的 API。技术选型二选一（Node.js Express/Koa 或 Java Spring Boot），确定后更新本文件。

## 规划结构

```
backend/
├─ src/
│  ├─ routes/         路由：只做参数校验与协议转换
│  ├─ services/       业务规则：约束校验、状态机、事务边界
│  ├─ models/         实体与数据访问
│  ├─ middlewares/    登录态解析、角色与数据范围注入、脱敏序列化
│  └─ jobs/           定时任务：超时未签到释放（每分钟）
└─ README.md
```

## 必须守住的三条

1. **校验顺序固定**：登录态与角色 → C-09 停权 → C-01 窗口 → C-03 粒度 → C-02 时长 → C-04 时间合法 → C-10 维护窗口 → C-05 重叠 → C-06 间隔 → C-07 并发写入，第一个不满足即返回。
2. **数据范围在服务端派生**：查询条件由登录态注入，列表接口不接受前端传入的 `user_id` / `resource_id`，越界返回 403。
3. **脱敏在序列化层统一实现**：手机号 `138****5678`，姓名 `张*`，`openid` 一律不返回。

## 接口约定

- 路径前缀 `/api/v1/`，学生端与管理端分离（`/api/v1/...` 与 `/api/v1/admin/...`）
- 错误响应统一给出 `code` + `message`，`code` 取值见需求说明书表 3-2
- 时段一律用 `[start_at, end_at)` 左闭右开区间，时间为 Asia/Shanghai
